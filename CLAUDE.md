# УГМК-Здоровье · тестовый Telegram-бот травмпункта

## Что делаем
Тестовая версия ИИ-ассистента травмпункта клиники «УГМК-Здоровье» (Екатеринбург) в Telegram. Бот ведёт пациента по сценариям колл-центра: жалоба → уточняющие вопросы → врач и свободное время → запись → напоминания → опрос после приёма → запись на контрольный приём → тот же цикл для второго приёма. Кроме того, бот отвечает на вопросы о травмпункте. Заказчик — клиника, разработчик — AMA IT Consulting.

Источник правды по логике — скрипты колл-центра в `kb/text/` (выгрузка из внутренней вики клиники от 18.08.2026). Полное ТЗ — `docs/spec.md`, карта скриптов — `docs/scripts_overview.md`, приёмочные тесты — `docs/test_cases.md`.

## Стек
- Python 3.12, менеджер пакетов uv
- aiogram 3 — Telegram (long polling)
- openai (Python SDK) с `base_url` DeepSeek — LLM
- SQLAlchemy 2 (async) + SQLite через aiosqlite — данные теста (позже Postgres)
- APScheduler — напоминания; задачи хранить в БД, чтобы переживали рестарт
- pydantic / pydantic-settings — схемы и конфиг из `.env`
- pytest + pytest-asyncio; ruff — линтер и форматтер

## Жёсткие правила
1. Бот не ставит диагнозы, не оценивает тяжесть и не советует лечение. Он только ведёт по маршруту: куда и к кому обратиться, запись, справка.
2. Ветку сценария выбирает код по JSON-сценарию. LLM только определяет, какой сценарий подходит, извлекает ответы пациента в структуру, формулирует реплики в тоне операторских фраз из скриптов и отвечает на вопросы по `kb/info`.
3. Врачей, время, цены и адреса бот берёт только из данных (`kb/`, `data/schedule.csv`, `config/`). LLM их не придумывает. Если данных нет, бот так и говорит и предлагает связаться с администратором.
4. Персональные данные (ФИО, дата рождения, телефон, username, chat_id) не отправляются в DeepSeek. В LLM уходит только текст жалобы или вопроса после маскирования: имена, телефоны, даты, e-mail заменяются плейсхолдерами. Это покрыто тестом.
5. Случаи из раздела 5 скриптов (голова, глаза, ЛОР, криминальная травма, дети до 6 месяцев и т. д.) не записываются: бот даёт маршрут из скрипта с адресом. При признаках угрозы жизни бот сразу советует вызвать скорую (103 или 112); список признаков согласуется с клиникой (см. открытые вопросы в ТЗ).
6. Где скрипт говорит «переводи на оператора взрослого КЦ (т. 1102)», бот передаёт обращение администратору в `ADMIN_CHAT_ID` с кратким контекстом и сообщает пациенту, что с ним свяжутся. Телефон КЦ для пациента — TODO в `config/contacts.yaml`.
7. Тексты пациенту — по-русски, на «Вы», коротко, в духе операторских фраз из скриптов.
8. Пропуски в скриптах (например, «Стоимость консультации (…..) рублей») не заполняются выдуманными значениями. Цены лежат в `config/prices.yaml`: сейчас это демо-цены первичного и повторного приёма с `demo: true`, бот помечает их «(демо-цена)»; настоящие впишет заказчик. Если значения нет (`null`), бот говорит «стоимость уточнит администратор».

## Конвенции
- Код и комментарии — на английском, тексты для пациента — на русском (в `app/bot/texts.py` или yaml).
- Время клиники — Asia/Yekaterinburg, в БД — UTC.
- Конфиг только через `app/config.py`, секреты только в `.env` (никогда не коммитить).
- Юнит-тесты не ходят в сеть: LLM и Telegram мокаются. Живой тест DeepSeek помечен `@pytest.mark.live` и запускается вручную.
- После каждого этапа: `uv run ruff check . && uv run pytest`, затем коммит с понятным сообщением и push.
- Перед крупными решениями (новая зависимость, смена архитектуры, платные сервисы) — спросить меня.

## Команды
- `uv sync` — зависимости
- `uv run python -m app` — запуск бота
- `uv run pytest` — тесты (`uv run pytest -m live` — с реальным DeepSeek)
- `uv run ruff check . --fix && uv run ruff format .`
