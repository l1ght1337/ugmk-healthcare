# ugmk-healthcare

Тестовый Telegram-бот травмпункта «УГМК-Здоровье» (Екатеринбург). Бот ведёт пациента по скриптам колл-центра:
1. жалоба;
2. уточняющие вопросы;
3. запись по демо-расписанию;
4. напоминания;
5. опрос после приёма;
6. контрольный приём.

Кроме того, бот отвечает на вопросы о травмпункте. Разработчик — AMA IT Consulting.

> Репозиторий должен оставаться приватным: в `kb/` — внутренние материалы клиники.

## Как это устроено
- **Ветку сценария выбирает код.** Сценарии в `kb/scenarios/*.json` собраны из скриптов `kb/text/`. Движок `app/flow/engine.py` выбирает ветку по ответам. У каждого вопроса есть кнопки, так что пройти весь путь можно без LLM.
- **DeepSeek** (`app/llm/`) только:
  - выбирает сценарий по жалобе;
  - разбирает свободный ответ;
  - отвечает на вопросы по справке `kb/info/`.

  Если он не ответил за 10 секунд или вернул ошибку, бот показывает кнопки.
- **Данные только из файлов.** Врачи, время, адреса и цены берутся из `kb/`, `config/` и `data/schedule.csv`. Пропуски в скриптах не заполняются: где данных нет, бот пишет «уточнит администратор». Цены первичного и повторного приёма пока демонстрационные (`config/prices.yaml`, `demo: true`), бот помечает их «(демо-цена)».
- **Персональные данные в DeepSeek не уходят.**
  - Имена, телефоны, e-mail, логины, номера документов, даты рождения и даты рядом с именем заменяются плейсхолдерами.
  - Даты событий переводятся в относительное время: «упал 10 ноября» → «упал 2 дня назад».
  - Это покрыто тестами `tests/test_privacy.py`.
- **Согласие.** До ввода ФИО и телефона бот спрашивает согласие на обработку данных; если запись для ребёнка — ещё «я законный представитель ребёнка». Командой `/forget` пользователь удаляет свои данные и записи.
- **Передача администратору.** Где скрипт говорит «переводи на КЦ (т. 1102)» или «запиши на плановый приём», бот передаёт обращение в чат администраторов (`ADMIN_CHAT_ID`) с ответами пациента. Администратор отвечает реплаем, бот пересылает ответ пациенту. Непонятный или посторонний текст администратору не уходит — только по кнопке; одно открытое обращение на пользователя, не больше 3 в сутки (`HANDOFF_DAILY_LIMIT`).
- **Свободный текст** классифицируется одним вызовом DeepSeek на десять типов: жалоба на травму, просьба о действии бота, медицинский вопрос, вопрос о травмпункте, вопрос о боте, отзыв, другое отделение клиники, жалоба не по профилю, посторонняя просьба, слова о риске для жизни (таблица — `docs/spec.md`, раздел 3). Слова о риске для жизни бот проверяет и по списку фраз в `config/clinic.yaml` до всего остального.
- **Мастер записи в одном сообщении.** Кнопка меняет сообщение на следующий шаг («Шаг N из 5», «Назад»). Темы — по тому, что случилось, и только для названной области тела (`kb/scenarios/_menu.json`). Время — кнопка «Ближайшее: сегодня, 14:30», день, время суток («Утро 8–12» … «Ночь 23–8»; если свободных времён в дне не больше восьми — сразу сетка), сетка по 4 в ряд с врачом смены. Подтверждение — карточкой (Telegram rich message, запасной вариант — обычный текст), ответы на вопросы — с «печатает…» и черновиком по мере генерации.
- **Пожелания: врач, день, время.** «Запиши меня к Ярунину на завтра утром» — врача, день и время суток разбирает код (`app/flow/wishes.py`), без DeepSeek. Бот подтверждает строкой «Пожелание: …», задаёт обычные вопросы сценария и на шаге «День и время» сразу открывает нужный день с временем этого врача. Если врач не дежурит или времени нет, бот говорит это прямо и предлагает ближайшее время у врача, этот же день у другого врача или другой день. На вопросы «кто принимает завтра?», «когда работает Ярунин?», «есть время сегодня вечером?» тоже отвечает код — по расписанию.
- **Без тупиков.** «Назад», «в меню», «отмена» текстом работают на любом шаге; подпись кнопки можно набрать словами («бытовая», «вечер», «14:30»); вопрос посреди записи получает ответ, и запись продолжается с того же шага; «подтверждаю», «я не приду», «запишите ребёнка», «спасибо» понимает код, без DeepSeek. 73 фразы на всех шагах — `docs/intent_matrix.md`, проверяет `tests/test_intents.py`. Текст на экране тем не возвращает назад и не сбрасывает пожелание; «перенеси на завтра» и «отмени и запиши на воскресенье» сразу открывают выбор времени с кнопкой «Оставить как есть»; «какие у вас врачи?» — список врачей с должностями и «Сейчас дежурит». На каждом экране записи — «Назад» и «Меню»; «Меню» не стирает начатую запись («Продолжить запись»). Вопрос «что делать?» вместе с жалобой получает ответ без медицинских советов, и запись идёт дальше.
- **Записи в чате администраторов (для теста).** С `BOOKINGS_TO_ADMIN_CHAT=true` каждая запись приходит карточкой: номер, дата и время, врач, первичный или повторный приём, тема, пациент, телефон, оплата. Перенос, отмена, «Как прошёл приём?» и оценка — ответом на карточку; `/today` в чате — записи на сегодня и завтра.
- **Удобство.** Приветствие с примерами и кнопками-примерами; перед выбором времени — сводка ответов с кнопкой «Изменить ответы»; под просьбой о ФИО и телефоне — зачем они нужны; под ответом на вопрос — «Помогло» и «Позвать администратора»; если пациент бросил запись, через 15 минут бот один раз напомнит (ночью — нет, `config/clinic.yaml`).
- **Вид.** Карточка записи строками с иконками; иконки на кнопках тем и главного меню; ролики и фото из `assets/` (см. `assets/README.md`, `MEDIA_ENABLED`); карточка записи закрепляется в чате без уведомления и открепляется при отмене или переносе; реакции 👍 на подтверждение визита и ❤ на оценку 5; длинные фразы скриптов — коротко, с кнопкой «Подробнее» (`kb/scenarios/_short.json`); в напоминании за 2 часа — фото входа и кнопка «Как пройти».
- **Расписание.** Пока нет доступа к «Медиалогу», используется демо-расписание `data/schedule.csv` на 21 день: четыре врача, один в смене. Правила повторного приёма — из скрипта 04-09. Записи помечаются как демонстрационные. Файл в git не хранится: бот строит его при старте и каждый день дописывает новый день.

## Запуск
```bash
uv sync
cp .env.example .env        # заполните: подсказки — в комментариях файла
uv run python -m app
```
Бот работает через long polling. База `data/bot.db` и журнал токенов `data/llm_usage.jsonl` создаются сами и в git не попадают. Демо-расписание само дополняется до 21 дня вперёд и пересобирается, если поменялись настройки в `config/schedule.yaml`. Пересоздать его вручную: `uv run python -m app.schedule.generate`.

### Docker
```bash
docker build -t ugmk-bot .
docker run -d --name ugmk-bot --restart unless-stopped \
  --env-file .env -v "$PWD/data:/app/data" ugmk-bot
```
Секреты передаются только через `--env-file`, в образ они не попадают. В образ не попадают и `kb/text`, `kb/source_pdf`, тесты.

### Настройки `.env`
| Переменная | Что это |
|---|---|
| `TELEGRAM_BOT_TOKEN` | Токен бота от @BotFather |
| `ADMIN_CHAT_ID` | Группа администраторов. Туда добавляется бот, туда приходят обращения и запросы доступа |
| `ALLOWED_USER_IDS` | Telegram ID участников теста через запятую; пусто — бот доступен всем. Остальных администратор пускает кнопкой «Разрешить» в группе, без правки `.env` |
| `DEEPSEEK_API_KEY`, `DEEPSEEK_BASE_URL`, `DEEPSEEK_MODEL` | DeepSeek. Без ключа бот работает только кнопками |
| `LLM_TIMEOUT_SECONDS` | Сколько ждать DeepSeek (10) |
| `LLM_USAGE_LOG` | Журнал токенов по каждому вызову, без текстов, — для расчёта стоимости |
| `MISSES_LOG` | Журнал непонятого (`data/misses.jsonl`), см. ниже; пусто — журнал выключен |
| `SCHEDULE_PROVIDER` | `mock` — демо-расписание; `medialog` — заглушка до доступа к API |
| `DEMO_MODE` | Включает команду `/demo_next` |
| `TIMEZONE`, `DATABASE_URL`, `LOG_LEVEL` | Часовой пояс клиники (в БД — UTC), база, уровень логов |

### Команды бота
- `/start` — приветствие и меню;
- `/menu` — меню;
- `/admin` — позвать администратора;
- `/forget` — удалить свои данные и отозвать согласие;
- `/demo_next` (при `DEMO_MODE=true`) — сразу прислать следующее уведомление: напоминание за 24 часа, за 2 часа, опрос после приёма и так далее.

## Журнал непонятого
Каждый раз, когда бот отвечает запасной фразой или передаёт вопрос администратору, в `data/misses.jsonl` (`MISSES_LOG`) дописывается строка: время, шаг диалога, тип ответа и текст пациента после маскирования (имена, телефоны, даты, e-mail заменены плейсхолдерами). Идентификатора пользователя, чата и имени в строке нет: журнал нужен, чтобы находить пробелы, а не читать переписку. Файл в git не попадает.

Типы: «нет информации» («У меня нет этой информации»), «выберите кнопкой», «не по теме» («Я помогаю только с…»), «не наш профиль», «не текст» («Я понимаю только текст и кнопки»), «подсказка после route» (текст на шаге с кнопками не понял ни код, ни DeepSeek), «не понял сообщение», «не разобрал данные» (ФИО, дата рождения, телефон, возраст), «DeepSeek не ответил», «передано администратору».

Команда `/misses` в группе администраторов показывает счётчик по типам за последние 24 часа и последние 20 строк.

## Тесты
```bash
uv run ruff check . && uv run pytest     # без сети: LLM и Telegram подменены
uv run pytest -m live -s                 # живой DeepSeek (нужен ключ), печатает токены и долю кэша
uv run python -m tests.live_report       # последние 3 live-прогона: тест, причина сбоя, время
uv run python -m tests.simulate          # симулятор пациентов (нужен ключ) → docs/simulation_report.md
uv run python -m tests.simulate --recheck  # те же расшифровки, правила заново, без DeepSeek
```
- `tests/simulate.py` — симулятор пациентов, запускается вручную, как live-тесты. DeepSeek играет 50 персонажей из `tests/simulate_personas.py` (мать с ребёнком ночью, пожилой человек, подросток, пишущий с опечатками или транслитом, раздражённый, передумывающий и т. д.) против настоящего диалога бота, до 25 ходов; пациент сам решает, нажать кнопку или написать. После диалога расшифровку проверяют правила без LLM: цель достигнута или получен понятный отказ с выходом; экран не показан дважды подряд без новой строки; вопрос не остался без ответа; названные врач, день и «для кого» не потерялись; у каждого ответа есть кнопка дальше; нет диагнозов и советов. Итог — `docs/simulation_report.md`: сколько диалогов прошло и расшифровка каждого провала. Имена и телефоны персонажей вымышленные. Опции: `--only ключ1,ключ2`, `--limit N`, `--parallel K`. Правила проверены офлайн в `tests/test_simulate.py`.
- `tests/test_acceptance.py` — исходы движка по кейсам из `docs/test_cases.md`.
- `tests/test_manual_cases.py` — все 20 приёмочных кейсов одним аккаунтом через логику диалога, как в Telegram.
- `docs/manual_test.md` — те же шаги для ручного прогона в Telegram. Собирается командой `uv run python -m tests.manual_cases --write`.
- `docs/button_labels.md` — подписи всех кнопок. Собирается командой `uv run python -m app.bot.labels --write`.

## Структура
```
app/
  __main__.py      запуск: БД, расписание, DeepSeek (с прогревом кэша), бот, планировщик
  config.py        настройки .env и данные config/*.yaml
  bot/             conversation.py — диалог без привязки к мессенджеру; telegram.py — aiogram;
                   access.py — доступ к тесту; render.py, texts.py — тексты пациенту
  flow/            схема и загрузка сценариев, движок, проверка угрозы жизни, возраст, ФИО
  llm/             клиент DeepSeek, промпты, маскирование, проверки ответов, учёт токенов
  schedule/        интерфейс расписания, демо (data/schedule.csv), правила 04-09, «Медиалог»
  notify/          какие уведомления и когда; планировщик (опрос таблицы reminders)
  db/              модели SQLAlchemy (SQLite), время в UTC
config/            цены, контакты, флаги, расписание (значения не из скриптов — TODO)
kb/                text/ — скрипты клиники; scenarios/ — сценарии; info/ — справка
docs/              ТЗ, карта скриптов, кейсы, исходы, ручной прогон, кнопки, запросы к клинике
```

## Что ждём от клиники
Полный список — в `docs/clinic_requests.md`. Главное:
- телефон колл-центра для пациентов и номер линии скорой помощи клиники;
- ссылка на политику обработки персональных данных;
- страницы «Не принимаем» и «Самостоятельное посещение старше 15 лет»;
- наличие антирабической вакцины;
- часы работы администраторов и доступ к «Медиалогу»;
- подтверждение формулировок, которые добавлены в бот сверх скриптов.

Настоящие цены первичного и повторного приёма впишет заказчик в `config/prices.yaml` (сейчас демо).
