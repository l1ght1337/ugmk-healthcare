# ugmk-healthcare

Тестовый Telegram-бот травмпункта «УГМК-Здоровье» (Екатеринбург). Бот ведёт пациента по скриптам колл-центра:
1. жалоба;
2. уточняющие вопросы;
3. запись по демо-расписанию;
4. напоминания;
5. опрос после приёма;
6. контрольный приём.

Кроме того, бот отвечает на вопросы о травмпункте. Разработчик — AMA IT Consulting.

> Репозиторий должен оставаться приватным: в `kb/` — внутренние материалы клиники.

## Как это устроено
- **Ветку сценария выбирает код.** Сценарии в `kb/scenarios/*.json` собраны из скриптов `kb/text/`. Движок `app/flow/engine.py` выбирает ветку по ответам. У каждого вопроса есть кнопки, так что пройти весь путь можно без LLM.
- **DeepSeek** (`app/llm/`) только:
  - выбирает сценарий по жалобе;
  - разбирает свободный ответ;
  - отвечает на вопросы по справке `kb/info/`.

  Если он не ответил за 10 секунд или вернул ошибку, бот показывает кнопки.
- **Данные только из файлов.** Врачи, время, адреса и цены берутся из `kb/`, `config/` и `data/schedule.csv`. Пропуски в скриптах не заполняются: где данных нет, бот пишет «уточнит администратор». Цены первичного и повторного приёма пока демонстрационные (`config/prices.yaml`, `demo: true`), бот помечает их «(демо-цена)».
- **Персональные данные в DeepSeek не уходят.**
  - Имена, телефоны, e-mail, логины, номера документов, даты рождения и даты рядом с именем заменяются плейсхолдерами.
  - Даты событий переводятся в относительное время: «упал 10 ноября» → «упал 2 дня назад».
  - Это покрыто тестами `tests/test_privacy.py`.
- **Согласие.** До ввода ФИО и телефона бот спрашивает согласие на обработку данных; если запись для ребёнка — ещё «я законный представитель ребёнка». Командой `/forget` пользователь удаляет свои данные и записи.
- **Передача администратору.** Где скрипт говорит «переводи на КЦ (т. 1102)» или «запиши на плановый приём», бот передаёт обращение в чат администраторов (`ADMIN_CHAT_ID`) с ответами пациента. Администратор отвечает реплаем, бот пересылает ответ пациенту. Непонятный или посторонний текст администратору не уходит — только по кнопке; одно открытое обращение на пользователя, не больше 3 в сутки (`HANDOFF_DAILY_LIMIT`).
- **Свободный текст** классифицируется одним вызовом DeepSeek: жалоба на травму, вопрос о травмпункте, не по профилю, посторонняя просьба, слова о риске для жизни (их бот проверяет и по списку фраз в `config/clinic.yaml` до всего остального).
- **Мастер записи в одном сообщении.** Кнопка меняет сообщение на следующий шаг («Шаг N из 5», «Назад»). Темы — по тому, что случилось, и только для названной области тела (`kb/scenarios/_menu.json`). Время — сначала день, потом сетка по 4 в ряд с врачом смены. Подтверждение — карточкой (Telegram rich message, запасной вариант — обычный текст), ответы на вопросы — с «печатает…» и черновиком по мере генерации.
- **Расписание.** Пока нет доступа к «Медиалогу», используется демо-расписание `data/schedule.csv` на 21 день: четыре врача, один в смене. Правила повторного приёма — из скрипта 04-09. Записи помечаются как демонстрационные.

## Запуск
```bash
uv sync
cp .env.example .env        # заполните: подсказки — в комментариях файла
uv run python -m app
```
Бот работает через long polling. База `data/bot.db` и журнал токенов `data/llm_usage.jsonl` создаются сами и в git не попадают. Демо-расписание само дополняется до 21 дня вперёд и пересобирается, если поменялись настройки в `config/schedule.yaml`. Пересоздать его вручную: `uv run python -m app.schedule.generate`.

### Docker
```bash
docker build -t ugmk-bot .
docker run -d --name ugmk-bot --restart unless-stopped \
  --env-file .env -v "$PWD/data:/app/data" ugmk-bot
```
Секреты передаются только через `--env-file`, в образ они не попадают. В образ не попадают и `kb/text`, `kb/source_pdf`, тесты.

### Настройки `.env`
| Переменная | Что это |
|---|---|
| `TELEGRAM_BOT_TOKEN` | Токен бота от @BotFather |
| `ADMIN_CHAT_ID` | Группа администраторов. Туда добавляется бот, туда приходят обращения и запросы доступа |
| `ALLOWED_USER_IDS` | Telegram ID участников теста через запятую; пусто — бот доступен всем. Остальных администратор пускает кнопкой «Разрешить» в группе, без правки `.env` |
| `DEEPSEEK_API_KEY`, `DEEPSEEK_BASE_URL`, `DEEPSEEK_MODEL` | DeepSeek. Без ключа бот работает только кнопками |
| `LLM_TIMEOUT_SECONDS` | Сколько ждать DeepSeek (10) |
| `LLM_USAGE_LOG` | Журнал токенов по каждому вызову, без текстов, — для расчёта стоимости |
| `SCHEDULE_PROVIDER` | `mock` — демо-расписание; `medialog` — заглушка до доступа к API |
| `DEMO_MODE` | Включает команду `/demo_next` |
| `TIMEZONE`, `DATABASE_URL`, `LOG_LEVEL` | Часовой пояс клиники (в БД — UTC), база, уровень логов |

### Команды бота
- `/start` — приветствие и меню;
- `/menu` — меню;
- `/admin` — позвать администратора;
- `/forget` — удалить свои данные и отозвать согласие;
- `/demo_next` (при `DEMO_MODE=true`) — сразу прислать следующее уведомление: напоминание за 24 часа, за 2 часа, опрос после приёма и так далее.

## Тесты
```bash
uv run ruff check . && uv run pytest     # без сети: LLM и Telegram подменены
uv run pytest -m live -s                 # живой DeepSeek (нужен ключ), печатает токены и долю кэша
```
- `tests/test_acceptance.py` — исходы движка по кейсам из `docs/test_cases.md`.
- `tests/test_manual_cases.py` — все 20 приёмочных кейсов одним аккаунтом через логику диалога, как в Telegram.
- `docs/manual_test.md` — те же шаги для ручного прогона в Telegram. Собирается командой `uv run python -m tests.manual_cases --write`.
- `docs/button_labels.md` — подписи всех кнопок. Собирается командой `uv run python -m app.bot.labels --write`.

## Структура
```
app/
  __main__.py      запуск: БД, расписание, DeepSeek (с прогревом кэша), бот, планировщик
  config.py        настройки .env и данные config/*.yaml
  bot/             conversation.py — диалог без привязки к мессенджеру; telegram.py — aiogram;
                   access.py — доступ к тесту; render.py, texts.py — тексты пациенту
  flow/            схема и загрузка сценариев, движок, проверка угрозы жизни, возраст, ФИО
  llm/             клиент DeepSeek, промпты, маскирование, проверки ответов, учёт токенов
  schedule/        интерфейс расписания, демо (data/schedule.csv), правила 04-09, «Медиалог»
  notify/          какие уведомления и когда; планировщик (опрос таблицы reminders)
  db/              модели SQLAlchemy (SQLite), время в UTC
config/            цены, контакты, флаги, расписание (значения не из скриптов — TODO)
kb/                text/ — скрипты клиники; scenarios/ — сценарии; info/ — справка
docs/              ТЗ, карта скриптов, кейсы, исходы, ручной прогон, кнопки, запросы к клинике
```

## Что ждём от клиники
Полный список — в `docs/clinic_requests.md`. Главное:
- телефон колл-центра для пациентов и номер линии скорой помощи клиники;
- ссылка на политику обработки персональных данных;
- страницы «Не принимаем» и «Самостоятельное посещение старше 15 лет»;
- наличие антирабической вакцины;
- часы работы администраторов и доступ к «Медиалогу»;
- подтверждение формулировок, которые добавлены в бот сверх скриптов.

Настоящие цены первичного и повторного приёма впишет заказчик в `config/prices.yaml` (сейчас демо).
