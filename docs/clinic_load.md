## Расчёт стоимости DeepSeek
Число вызовов на одно обращение (по устройству бота):

| Обращение | Вызовы LLM |
|---|---|
| Запись только кнопками | 0 |
| Запись, жалоба написана текстом, дальше кнопки | 1 (`route`) |
| Запись, ответы на вопросы сценария текстом | 1 + по одному `extract` на каждый текстовый ответ (обычно 1–3) |
| Вопрос о травмпункте | 2 (`route` + `answer`) |
| Посторонний текст, не по профилю, кризис | 1 (`route`) |

Замеры токенов на один вызов (журнал `data/llm_usage.jsonl`, 12.11.2026, до расширения `route` в ноябре; после изменений промптов цифры нужно перемерить командой `uv run pytest -m live -s`):

| Задача | Токенов на входе | Из кэша DeepSeek | Токенов на выходе | Время ответа |
|---|---|---|---|---|
| `route` | ~5 150 | ~4 990 (97 %) | 20–50 | ~1,8 с |
| `answer` | ~2 220 | ~2 050 (92 %) | 15–60 | ~1,5 с |
| `extract` | как `route` (тот же системный промпт) | ~97 % | 20–40 | ~1,5 с |

Оценка на день, если все 90 обращений идут через бота и в среднем на обращение 2 вызова:
- 180 вызовов в день, в пик — до 30 в час;
- входных токенов ≈ 180 × 5 000 = 0,9 млн в день, из них ~0,87 млн — попадания в кэш;
- выходных токенов ≈ 180 × 40 = 7 тыс. в день.

Стоимость в день = кэш-токены × цена кэш-попадания + остальные входные × цена входа + выходные × цена выхода. Цены берите с platform.deepseek.com на дату расчёта: они меняются, поэтому в репозитории их нет. При 128 обращениях в день (верхняя граница от клиники) умножайте на 1,4.

## Надёжность вызовов (live-прогоны 13.11.2026)
Три прогона `uv run pytest -m live` подряд: 33 теста × 3, 96 вызовов DeepSeek, сбоев нет. Время ответа: медиана 1,5 с, 95 % — 2,3 с, максимум 2,5 с при лимите 10 с. Причина каждого сбоя (таймаут, сеть, HTTP-код, неверный JSON, неверная структура ответа) пишется в `data/llm_usage.jsonl` (поле `reason`); сводка live-прогонов — `uv run python -m tests.live_report`.
